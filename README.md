## 使用顺序

1. 读模板 README，核对用途、当前限制和所需客户端能力。
2. 导入该目录的单个 ZIP，安装后创建自己的实例。
3. 通过 UI 配置自己的参数、资源和独立动作授权，再按说明运行。
4. 阅读实际结果与待办；失败、取消或 unknown 不自动重放。

BOSS 当前先收口首次沟通，正式回复、简历附件和联系方式在后续范围；网站当天真实上限仍待验收。MCP 暂缓。个人模板也仍为候选，草稿与最终确认保存分别核对。

## 维护与构建

`templates/` 是使用者交付目录，每个模板只保留 README 和当前 ZIP。`development/` 是源码制作的示例与共享开发代码；BOSS 和个人模板从客户端作者 UI 维护并导出，ZIP 是完整定义来源，不保存重复展开副本。`catalog.json` 登记唯一当前交付，`client-checkpoints.json` 固定客户端原始归档摘要。旧检查点由 Git 历史追溯；旧包隐私问题不会因移出当前目录而视为已召回。

```sh
pnpm install --frozen-lockfile
pnpm validate          # 检查全部当前 ZIP、源码、README 与固定来源
pnpm build             # 统一输出全部 9 个当前模板至 dist/
pnpm package:templates # 显式更新源码示例 ZIP；不重打包客户端原始 ZIP
```

源码和 README 变更须递增模板版本并同步 catalog，再显式打包。客户端模板通过作者 UI 修改版本、入口或 README 后导出到对应目录，再更新原始摘要登记。`validate` 和 `build` 不改写交付文件。完整性、复导、运行和业务验收分别记录。当前 UI 阶段不新增或运行单元测试；已有测试保留，`pnpm check` 包含测试，不作为本阶段命令。

不提交凭据、简历、登录态或运行记录，不依赖相邻客户端仓库。架构、契约与开发验收资料集中在治理仓库，当前独立采用版本见 package.json。
